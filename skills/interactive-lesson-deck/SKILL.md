# 互動教學簡報網站（Interactive Lesson Deck）

協助使用者把教材轉成教師可投影、學生可操作的互動教學網站。預設交付單一 HTML 檔，除非教材規模或使用情境需要多檔案。先讀取來源，再規劃頁面與互動，逐步製作並檢查成品。

這份 Skill 遵循 Agent Skills 的通用 `SKILL.md` 格式，不依賴特定 AI Agent、瀏覽器、MCP 服務或作業系統。各環境的工具名稱與能力不同；執行時只使用目前實際可用的檔案、PDF、瀏覽器、程式執行與視覺檢查工具。沒有某項工具時，採用可行替代方法，並清楚說明尚未驗證的部分。

## 成品方向

- 優先使用可直接用瀏覽器開啟的單一 HTML；有必要才拆成多個本機檔案，並一併交付。
- 預設以 16:9 投影畫面設計，整體可依視窗縮放；重要文字與操作區應在教室後排可讀。
- 每頁聚焦一個學習重點。概念說明與練習可分頁，也可依教學節奏合併，但不可讓重點互相競爭。
- 能以操作呈現的概念，使用中央圖解、模型或可操作視覺；操作應直接改變圖解狀態，必要時同步更新例句、提示或答案。
- 練習的題目與答案欄應放在視覺流程自然的位置；若題目要求根據圖像作答，圖像必須提供足夠線索。
- 視課堂需求加入目錄、上一頁／下一頁、重設、暫停、放大、講解面板、繪圖或雷射筆等教師工具。不要為了符合清單而加入不需要的功能。
- 色彩、字體、圖示與動畫服務教學辨識和閱讀；顏色角色盡量一致，避免裝飾搶走注意力。

可參考 `assets/example-english-tenses.html` 的完整案例與 `assets/lesson-template.html` 的共用骨架。科目圖解構想見 `references/subject-patterns.md`，共用控制器介面見 `references/controller-contract.md`。這些是範例，不是所有課程都必須套用的固定規格。

## 工作流程

依序完成下列階段。若使用者已提供足夠資訊、明確指定範圍或要求直接製作，可略過重複詢問，直接進入相應階段。只在缺少的資訊會影響內容正確性、受眾適切性或重大設計選擇時提問；可合理判斷的細節由 Agent 採用保守預設，並簡短說明。

### 1. 確認任務與教材

確認或推知以下資訊：

- 目標學習者、年級或先備程度，以及課堂用途。
- 教材檔案、指定章節、要涵蓋的範圍和預期頁數或課程時間（若已知）。
- 學生會如何操作，及教師是否需要講解、投影或離線使用。

若教材尚未提供而且無法可靠地根據其他來源製作，請向使用者索取必要資料；可先完成不依賴教材的版型或技術準備。不要假裝讀過尚未取得的檔案。

### 2. 讀取與整理來源

- 先使用環境已有的 PDF／文件讀取能力；若沒有，選擇可用的本機工具。掃描頁面才需要 OCR。
- 交叉檢查擷取文字和頁面圖像；遇到亂碼、表格、公式或版面影響意思時，以可讀頁面為準並標明不確定處。
- 摘要單元架構、必要術語、核心概念和原教材中的例題。區分教材明載的事實與自行設計的示意情境。
- 優先沿用使用者有權使用的原教材例句或題目。若需另編例子，標示為自編示例，不杜撰來源或引用。
- 判斷哪些概念適合互動圖解，哪些更適合文字、時間線、地圖、比較表或靜態圖像。互動必須提升理解，不要為互動而互動。

### 3. 規劃頁面

先提出精簡逐頁規劃；若使用者明確要求直接製作，則將規劃納入實作並保持可檢視。可使用表格欄位：頁碼、學習重點、圖解或版型、學生操作、畫面與答案如何改變、來源依據。

若版型仍不明確，附簡單線框圖或文字示意。將複雜內容拆頁，避免把完整講解塞進投影畫面。對重要但尚未確定的內容提出選項；一般版面細節不必逐項打斷使用者確認。

### 4. 製作小型預覽並迭代

- 先製作能代表主要互動模式的少量頁面或一個可操作原型，除非使用者已要求完整成品，或此專案已核准的設計可直接沿用。
- 優先重用本 Skill 的樣板與共用元件；確認樣板與當前需求相符後再擴充，只替換科目專屬內容。
- 預覽應可實際操作；邀請使用者針對理解、操作、版面與視覺風格回饋。收到回饋後先修正共用規則，再擴充其餘內容。
- 若使用者希望一次完成，尊重該要求，並在交付前做可行的完整檢查。

### 5. 製作規則

- 圖解與題目要相互對應；練習題答案應來自目前畫面狀態或來源規則，不可讓圖像與答案脫節。
- 若題目會隨機變化，題幹、圖像、提示與正確答案需由同一份題目狀態產生，確保一致。
- 答案判定依科目調整：可忽略大小寫、空白或等價標點，但不可把不同意思的答案誤判為正確；容許多個答案時明確列出有效答案。
- 講解內容應依目前題目狀態即時產生，避免顯示上一題的說明。
- 拖曳或觸控操作要避免誤選文字；互動元素應有可見回饋，鍵盤操作也應合理。
- 手寫、繪圖或雷射筆若與舞台縮放共存，座標應對齊縮放後畫面；提供清除或重設方式。
- 避免依賴網路服務才能使用核心教材。若使用外部字型或媒體，離線時提供合理退回方案，並遵守授權與來源要求。
- 不要以動畫、音效或隨機效果取代教學說明；避免閃爍、過度動態或不適合目標年齡的操作設計。

### 6. 檢查與交付

使用目前環境能提供的檢查方式；工具名稱不限。完成前應盡可能：

1. 開啟成品並查看瀏覽器或執行環境錯誤訊息。
2. 檢查每一頁的實際版面，特別是文字溢出、重疊、裁切、對比、字級和投影可讀性。若無法逐頁查看，抽查代表頁並說明範圍。
3. 操作主要控制項，包括目錄跳頁、上一頁／下一頁、重設、練習作答和講解面板；若有拖曳、點選或滑桿，至少各試一次。
4. 若可程式化檢查，驗證每題的答案、講解和畫面狀態一致；至少涵蓋正確答案、錯誤答案、切換題目與重設等路徑。
5. 確認本機開啟或預定的分享方式可用；不要把成功產檔等同於已確認瀏覽器或裝置可用。

交付時回報檔案位置、涵蓋的主題與頁數、操作方式、實際完成的檢查，以及仍未能驗證的部分。若分享給其他教師，說明如何開啟、需否連網及所需檔案。

## 教學設計原則

| 原則 | 理由 |
|---|---|
| 一頁一個主要重點 | 投影資訊過多會降低辨識度，也不利於課堂節奏。 |
| 操作能改變學習模型 | 學生看見操作與結果的因果關係，才能用畫面理解規則。 |
| 圖像與問題相互支持 | 學生應能根據圖像推理作答，而不是猜答案或讀取互不相關的資訊。 |
| 先回饋，再按需查看講解 | 保留練習思考空間，也讓教師能掌握解說時機。 |
| 教師掌控課堂節奏 | 暫停、重設、跳頁與放大等功能依實際課程需求提供。 |
| 視覺編碼前後一致 | 固定顏色或形狀代表相同概念，可減少重複學習介面。 |

## 常見問題處理

- 修改失敗或檔案已變更：重新讀取最新內容，再以小範圍編輯；多步取代前檢查目標文字唯一性，避免覆蓋使用者新變更。
- 練習講解與目前題目不一致：將講解文字改為依目前題目狀態即時產生，並測試切題後的內容。
- 標籤碰到固定圖形或說明：為標籤保留空間，或依文字長度計算尺寸，不要只在單一題目上微調。
- 舞台縮放後畫筆／拖曳位置偏移：統一使用舞台座標系，並在不同視窗尺寸下確認位置。
- 版型檢查工具或瀏覽器不可用：採用可用替代方式，例如產生靜態截圖或做結構檢查；清楚標記未能完成的視覺或操作驗證，不宣稱已驗證。
