# 互動教學簡報網站（Interactive Lesson Deck）

把一份教材變成「老師在教室投影、學生上台操作」的網站。這個流程來自一次完整的實作（高職英文時態，11 個主題、22 頁），並吸收了使用者在過程中的每一次修正。**修正比初稿更值得照做**，所以下面的規則大多附有原因。

## 先理解成品長什麼樣

- 單一 HTML 檔，雙擊就能開，不需網路伺服器（英文字型可選用 Google Fonts，離線會退回系統字型）。
- 1920×1080 固定舞台，自動縮放；字體以投影為準（句子 56px、說明 ≥ 26px）。
- **每個主題 = 兩頁**：
  - **概念頁**：大圖解在中間，一句例句在圖下面，學生拖／點圖，句子跟著變；右下角「講解」按鈕。
  - **練習頁**：圖在中間，**題目句子在圖下面，空格就在句子裡**；老師輸入學生答案 → 對答案 → 看講解。
- 老師工具列：雷射筆、5 色畫筆、橡皮擦、垃圾桶（清本頁筆跡）、目錄、上一頁／下一頁、播放／暫停、重設、放大圖解。
- 馬卡龍色系（粉、天藍、薄荷、桃、薰衣草、檸檬）。

完整樣品：`assets/example-english-tenses.html`（22 頁成品，可當實作範例）。可直接複製的骨架：`assets/lesson-template.html`（已含全部共用功能和一個可跑的 demo 主題）。

## 流程（照順序，每一步都先跟使用者確認再往下）

### 0. 問清楚四件事（缺什麼問什麼，別一次問太多）
1. 對象與用途：幾年級／什麼程度、老師怎麼講、一節課多久。
2. 教材：請使用者把檔案放進工作資料夾；沒有檔案就先停下來等。
3. 範圍：整份還是先做一個系列？**建議先做最適合圖解的一個系列**，其餘之後再擴充。
4. 例句：盡量沿用教材原句（老師和學生都認得，也避免自己編造內容）。

### 1. 讀教材
PDF 用 `pypdf` 轉成文字存到 scratchpad 再讀（`pip install -q pypdf`）；掃描檔才需要 OCR。讀完回報：結構（單元、每單元重點）、教材裡哪些概念**適合圖解**、哪些不適合。

挑概念的標準：**學生動手之後，畫面的變化能直接說明規則**。詳細的「概念 → 圖解類型」對照見 `references/subject-patterns.md`（英文文法、數學、理化、史地、國文都有）。

### 2. 提出逐頁規劃（先規劃，不寫程式）
- 一張表：頁碼｜重點（一頁一件事）｜圖解｜**學生操作 → 畫面怎麼變**｜答案區。
- 附一張版型示意圖（可用 `mcp__visualize__show_widget` 畫 wireframe）：頂部標題列、中間大圖、下方一句、底部工具列。
- 等使用者明確說「好」才進下一步。**一頁一重點**：資訊多就拆頁，不要把講解文字塞進簡報頁。

### 3. 做少量預覽（2～3 頁），給使用者操作
挑互動型態最不同的 2～3 個主題（例如：滑桿、拖動物件、點選切換）。做完用瀏覽器實際操作驗證（見下方「驗證」），再請使用者評價。**不要一次做完全部**，因為版型和互動多半還要調。

### 4. 依回饋調整，再擴充到全部
使用者通常會在預覽階段修正這幾件事（已內建在骨架裡，不要退回去）：
- 不要「逐步揭示／按空白鍵出現說明卡」。滿版資訊違反一頁一重點；改成**概念頁／練習頁分開 + 講解面板（H 鍵）**。
- 不要把「看圖填空」和「上面例句填空」做成兩處。**只留句子裡的空格**。
- 題目在圖下面、不要放左右分欄；圖放大放中間，投影才看得清楚。
- 要有目錄，且每個主題可直接跳到「概念」或「練習」。
- 風格要精緻、馬卡龍色；工具列要有雷射筆、多色畫筆、橡皮擦、垃圾桶。

擴充時用 `assets/lesson-template.html` 當骨架，只寫科目特有的部分（見 `references/controller-contract.md`）。

### 5. 驗證（宣告完成之前一定要做）
用內建瀏覽器（`mcp__Claude_Browser__*`）：
1. `read_console_messages` 確認沒有錯誤。
2. 每一頁截圖看版面（標籤有沒有互相壓到、圖有沒有被切掉、字有沒有溢出）。
3. 用 JavaScript 對**每個練習頁**跑自動測試：重複「換一題 → 看答案 → 對答案」，確認都判為答對；再對每一頁開講解，確認沒有 `undefined`／`NaN`。
4. 實際拖一次、點一次，確認互動有反應（拖曳不要選到文字，所以 SVG 要 `user-select:none`）。
自動測試過了不代表版面沒問題，截圖不能省。

## 設計原則（為什麼這樣做）

| 原則 | 原因 |
|---|---|
| 一頁一重點，概念和練習分頁 | 投影上資訊一多後排就看不清；老師講完概念才開練習，節奏才對 |
| 圖在中間、題在圖下 | 學生先看圖、再讀題，答案要從圖裡找，不是從文字猜 |
| 空格就在題目句子裡 | 兩處填空會重複；老師輸入學生答案最自然的位置就是句子 |
| 答案先判斷、講解後看 | 對／錯先回饋，講解按需打開，避免一開始就洩題 |
| 每題隨機生成，答案由圖的狀態算出來 | 「看圖寫句子」才成立；換一題圖和句子一起變，不會出現圖與答案不一致 |
| 老師可控：暫停、重設、放大、遮答案、畫筆 | 課堂是老師主導，工具只是輔助 |
| 顏色固定代表同一種角色 | 例如動詞 = 藍、時間點 = 橘、Now = 紫；學生看久了不用重學 |

## 容易踩的坑
- **Edit 失敗訊息「檔案已被修改」**：重新 Read 再寫；多步修改用 Python 腳本加 `assert s.count(舊字串)==1`，比一長串 sed 安全。Windows 上別把含大量引號的多行 Python 直接塞進 bash `-c`，改寫成檔案再執行。
- 練習頁的**講解面板**要在打開時才組字串（用函式 `explain()`），這樣答案永遠跟當下這題一致。
- 答案比對要容忍大小寫、句尾標點、全形引號，且一個空格可接受多種正確答案（例如 `will take` 或 `are going to take`）。
- 標籤位置要避開固定元素（Now 線、區域標題）；圖下方的說明小字放在 SVG 圖內時，用 `S_.pill` 自動算寬度。
- 縮放的是整個 1920×1080 舞台；畫筆畫布座標也用 1920×1080，這樣放大縮小都不會偏位。

## 交付
- 檔案放使用者的工作資料夾，檔名用教材系列名稱。
- 回報：做了幾個主題／幾頁、操作鍵、已驗證的項目、**沒驗證的項目**（例如沒有逐頁用眼睛再看一次）。
- 若使用者要分享給其他老師：單一 HTML 檔直接寄送或放 USB 即可。
