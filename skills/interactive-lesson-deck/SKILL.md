# 互動教學簡報網站（Interactive Lesson Deck）

協助使用者把教材轉成教師可投影、學生可操作的互動教學網站。預設交付單一 HTML 檔，除非教材規模或使用情境需要多檔案。這份 Skill 使用通用 `SKILL.md` 格式，不依賴特定 AI Agent、瀏覽器、MCP 服務或作業系統；只使用目前實際可用的工具。

## 必須先確認，再開始製作

**使用者說「請用這個 Skill 幫我做網站」，代表要開始需求訪談與規劃，不代表同意直接寫程式或製作網站。**開始前必須先完成需求確認與 UI 規劃，清楚列出預計頁面、互動和視覺配置，並請使用者確認。未收到明確同意前，不得建立或修改網站 HTML、CSS、JavaScript、圖像或其他成品檔案，也不得以「先做預覽」為由提前開始。

若使用者已提供部分資訊，不要重問；只問會影響內容正確性、學習者適切性或 UI 選擇的缺項。使用者可在同一則訊息中確認規劃或指定沿用既有設計；「使用此 Skill」、「請幫我做網站」或上傳教材本身都不算規劃核准。若使用者明確要求跳過規劃，仍需先展示並確認 UI 方案，因為 UI 是本 Skill 的必要確認項目。

### 需求訪談要確認

按需要詢問下列項目，避免一次問太多：

- 學習對象、年級或先備程度、課堂用途與大致時間。
- 教材檔案、指定章節或主題範圍；確認素材已能讀取。教材未提供時不可假裝已讀取，也不可自行編造教材內容。
- 學生會如何操作、教師如何帶課、是否需要離線使用。
- 主要學習重點與需要互動或放大的內容，例如課文、化學式、幾何圖形、實驗圖或 3D 模型。

資訊足夠後，整理你的理解；明確標示來源事實、自編示意和仍待確認的內容。

### 提案並等待 UI 確認

提出一份簡短但具體的規劃，至少包含：

1. 頁面大綱：每頁的學習重點、圖解、學生操作，以及操作後如何更新畫面或答案。
2. 版面示意：頁首、主教材／互動區、題目或說明、導覽和工具的位置；用簡單 wireframe 或文字方位圖即可。
3. UI 設計：目錄如何開啟、工具列配置、放大功能的對象與操作方式、風格方向，以及投影和觸控考量。
4. 明確詢問使用者是否核准此規劃，或要修改哪些部分。

提案後停下來等待使用者回覆。只有取得明確核准，才能開始建立網站程式碼。使用者要求調整 UI 時，更新提案並再次確認受影響的部分；不要只在完成後才告知 UI 決定。

## 預設 UI 方向（仍須讓使用者確認或修改）

以下是預設提案，不是跳過使用者確認的理由：

- **左側目錄**：點擊目錄圖示後，從左側滑出課程側邊欄；不要用置中的彈出視窗遮住整個網站。顯示主題、頁次與目前位置，點選後側欄收回並切換頁面。
- **右側工具列**：畫筆、顏色、雷射筆、橡皮擦、清除筆跡等工具常駐右側，不折疊、不自動隱藏。以 icon 呈現；滑鼠懸浮和鍵盤焦點時顯示說明文字，並提供可存取名稱。觸控裝置需有清楚的選取狀態和說明方式。
- **重點放大**：每頁預設提供清楚的放大入口，可聚焦課文、化學式、幾何圖形、示意圖、照片或 3D 模型等主要學習物件。一般情況放大整個主要圖解區和重點文字；若需精確聚焦更小範圍，將 `data-primary-focus` 設在包住該內容的 HTML 容器上。放大時保留原物件狀態與操作能力，畫筆、雷射筆、橡皮擦和清除功能仍可用於放大中的內容；關閉後回到原頁和原狀態，筆跡仍對齊內容。
- **頁面導覽**：上一頁、下一頁和目前進度清楚可見，不與繪圖工具混在一起。
- **視覺方向**：優先讓學習重點大而清楚、投影易讀、操作可見；色彩、字型和裝飾依教材與使用者偏好選擇，不強制套用馬卡龍色系。

## 製作流程

### 1. 讀取與整理來源

- 先使用環境已有的 PDF／文件讀取能力；若沒有，選擇可用的本機工具。掃描頁面才需要 OCR。
- 交叉檢查擷取文字和頁面圖像；遇到亂碼、表格、公式或版面影響意思時，以可讀頁面為準並標明不確定處。
- 摘要單元架構、必要術語、核心概念和原教材中的例題。區分教材明載的事實與自行設計的示意情境。
- 優先沿用使用者有權使用的原教材例句或題目。若需另編例子，標示為自編示例，不杜撰來源或引用。
- 判斷哪些概念適合互動圖解，哪些更適合文字、時間線、地圖、比較表或靜態圖像。互動必須提升理解，不要為互動而互動。

### 2. 製作已核准的規劃

使用者核准後，才按規劃製作少量可操作預覽；除非使用者已核准完整製作，否則先用預覽確認版面與互動。若預覽顯示核心 UI 需改動，先整理差異和新方案，等使用者確認後再擴充。

優先參考 `assets/lesson-template.html` 的共用骨架，並按當前核准的 UI 方向修改；不要把模板的科目範例、顏色或固定佈局當成必須照抄。完整案例見 `assets/example-english-tenses.html`。科目圖解構想見 `references/subject-patterns.md`，控制器介面見 `references/controller-contract.md`。

### 3. 製作規則

- 每頁聚焦一個學習重點。複雜內容拆頁，不要把講解文字塞滿投影畫面。
- 圖解與題目相互對應；練習答案須由目前圖像狀態或來源規則推得。
- 若題目隨機變化，題幹、圖像、提示與正確答案須由同一份題目狀態產生。
- 答案判定依科目調整，不得把不同意思的答案誤判為正確；容許多個答案時明確列出。
- 講解依當前題目狀態產生，避免顯示前一題內容。
- 拖曳、點選或觸控操作要有清楚回饋，並避免誤選文字。
- 繪圖層須覆蓋目前聚焦／放大的教材內容，並依縮放後的座標正確標記。關閉放大後，筆跡留在該頁對應位置；清除工具只清除目前頁面筆跡。
- 核心教材避免依賴網路服務。外部字型或媒體需有離線退回方案，並遵守授權與來源要求。

### 4. 檢查與交付

依環境可用工具檢查成品；工具名稱不限。至少檢查：頁面有無溢出、重疊、裁切；左側目錄可滑出並正確跳頁；右側工具列固定可見且提示可讀；放大後教材可讀、仍可畫記並可正常還原；主要練習、重設與講解操作正常。若某項無法實際驗證，明確說明，不能把產檔成功說成網站已驗證。

交付時回報檔案位置、主題與頁數、操作方式、已檢查項目和未能驗證處。

## 教學設計原則

| 原則 | 理由 |
|---|---|
| 一頁一個主要重點 | 投影資訊過多會降低辨識度，也不利於課堂節奏。 |
| 操作能改變學習模型 | 學生看見操作與結果的因果關係，才能用畫面理解規則。 |
| 圖像與問題相互支持 | 學生應能根據圖像推理作答，而不是猜答案。 |
| 先回饋，再按需查看講解 | 保留練習思考空間，也讓教師掌握解說時機。 |
| 教師掌控課堂節奏 | 導覽、重設、放大與畫記功能服務課堂，不搶走教學主導權。 |
| 視覺編碼前後一致 | 固定顏色或形狀代表相同概念，可減少重複學習介面。 |

## 常見問題處理

- 使用者提出的內容和教材不一致：先指出差異並詢問要依哪個來源，不要自行選擇。
- 練習講解與目前題目不一致：依目前題目狀態即時產生講解，並檢查切題後的內容。
- 標籤碰到固定圖形或說明：預留空間或依文字長度計算尺寸。
- 舞台縮放後畫筆／拖曳位置偏移：統一使用舞台座標系，並檢查不同視窗尺寸。
- 瀏覽器或視覺檢查工具不可用：用可用替代方法檢查，並明確列出未能完成的項目。
